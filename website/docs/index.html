Understudy documentation

Understudy records Android UI tests on a virtual device or a real phone, turns typed values into Excel test data, and runs everything with the Maestro CLI — all on your own PC.

Understudy is a local web app with a desktop feel. A small Node.js server runs on 127.0.0.1, talks to your device through adb, writes Maestro flows into Flows/ and test data into TestData/, and runs the Maestro CLI for you. It opens in its own window and never needs an account or internet connection after setup.

New in 1.1: APK manager with a remove button, From device recording, placeholder targets, step types, conditions and loops, a two-way flow editor, a choice of Excel file and sheet, Wi-Fi phones, clean-state snapshots, much faster screen, and Android tools without Android Studio.

Install

1. Get the project

Clone the repository, or download the ZIP from GitHub and unzip it anywhere you like.

  Command Prompt
git clone https://github.com/daiyanHasin/understudy.git
cd understudy

2. Start Understudy

Double-click Understudy.vbs. The first start installs its components (about a minute, needs internet) and offers to add a desktop shortcut. Understudy then opens in its own window at http://understudy.localhost:4545.

3. Install the Maestro CLI

Follow the official instructions, then check it in a new terminal:

  Command Prompt
maestro --version
java -version

4. Install the Android tools

Open Setup and press Install Android tools. A PowerShell window downloads about 1.5 GB from Google's official server — command-line tools, platform-tools (adb), the emulator and one system image — and creates a light virtual device called Understudy_Pixel (2 GB RAM). You choose Android 13 (recommended), 14, or 12 (lightest).

Android Studio is not needed. If you already have the Android SDK, Understudy finds it through ANDROID_HOME or %LOCALAPPDATA%\Android\Sdk.

First run

The Setup checklist checks Node.js, Java, the Maestro CLI, the Android SDK, adb, the emulator, hardware acceleration, virtual devices and connected devices. Every red item shows how to fix it.

To stop Understudy, press Quit at the bottom of the sidebar. If you just close the window, Understudy stops by itself a few minutes later when nothing is running. start-gui.bat starts it with a visible console for troubleshooting.

Devices

The device picker sits at the top of the Record tab, with a refresh button (↻) and Stop / Disconnect. Add device opens the rest.

Virtual device

Choose a virtual device and press Start. By default it runs inside Understudy only, using your GPU (Graphics: fast). If it closes while starting, a red box shows the emulator's error and the full log is saved to logs/emulator-<name>.log. Try Graphics: compatible, and check Hardware acceleration in Setup.

Phone over USB

Turn on Developer options → USB debugging, plug the phone in and accept the prompt. It appears in the device list. Unplug the cable to disconnect.

Phone over Wi-Fi

On Android 11+, open Developer options → Wireless debugging. The first time, choose Pair device with pairing code and enter the pairing address and 6-digit code under First time? Pair with code. Then enter the IP address and port shown on the Wireless debugging screen and press Connect.

Clean state

For virtual devices: get the device how you want it (logged out, permissions granted, onboarding done), press Save clean state, and use Reset to clean state before recording or testing. Every session then starts from exactly the same point.

APKs and apps

The APK manager sits next to the app ID on the Record tab.

  • Add APK… copies an .apk into the local Apps/ folder. It is checked before it is stored and never uploaded anywhere.
  • Install installs the selected APK on the current device (with permissions granted) and fills in the app ID.
  • × removes the selected APK from Apps/, so you can add a newer build.

The app ID box also suggests every app already installed on the device. Launch app starts it, optionally with Fresh data (clears the app's storage first).

Recording a flow

  1. Choose or start a device.
  2. Add and install your APK, or pick an installed app ID.
  3. Name the flow, for example Login/login_valid.yaml, and add tags such as smoke, login.
  4. Press Launch app. A Launch app step is added.
  5. Click a field on the screen, type in the box under the device and press Enter. Choose Read from test data or Use this exact text.
  6. Continue through the flow. Use Back, Enter, Hide keyboard and Scroll under the device, or Insert for more.
  7. Save flow, or Save and run to run it straight away.

Press Ctrl + Z to remove the last step. The highlight on the screen shows exactly which element a step targets.

From device tips. Enter the app ID first. Tap at a normal pace: a tap made right as the screen changes may be saved as a screen position and is marked so you can fix it. Password text can't be read back, so Understudy asks for it.

Editing steps

Change the type

Each tap or check has a type menu: Tap, Double tap, Long press, Check visible, Check not visible, Scroll until visible, or + Type text after this.

Change the target

Understudy offers every way to find the element, best first:

  • ID — the developer's resource ID; the most stable choice.
  • Placeholder — the hint inside an empty field, such as “Enter email”. Works for classic and Jetpack Compose fields.
  • Text or Label — visible text or accessibility label.
  • Screen position — a last resort that can break on other screen sizes.

Targets that match more than one element are flagged. Choose Edit target… to type your own ID, text or position.

Move, delete, select

Use ▲ ▼ to move a step and × to delete it. Tick steps to delete them together or wrap them in a block.

Insert

Insert adds: wait for animations, hide keyboard, press Back, press Enter, scroll down, clear text, screenshot, and empty Repeat / If visible / Repeat while / Retry blocks.

Conditions and loops

Tick the steps, then choose Repeat, If visible, While visible or Retry in the bar above the list. Blocks can be nested, edited (times, visible / not visible, target) and unwrapped.

BLOCKMAESTRO COMMANDUSE IT FOR
Repeatrepeat: timesDoing something N times, e.g. adding 3 items.
Repeat whilerepeat: whileScrolling or dismissing until something appears or disappears.
If visiblerunFlow: whenPopups that only sometimes appear, like permission prompts.

      visible:

      - tapOn: "Allow"

Looping over data is different: each Excel row is run as a separate test from the Run tab (see Choosing rows).

Flow editor

The Flow panel on the right shows the YAML Understudy will save — and you can edit it. When you change it, the panel highlights and an Apply changes button appears. Press it (or Ctrl + Enter) and the step list is rebuilt from your YAML.

  • Any Maestro command Understudy doesn't know is kept as a Custom step, exactly as written.
  • The runScript line is managed for you and points at the chosen Excel sheet.
  • Paste an existing flow to continue recording it.
  • Saving with unapplied changes applies them first; YAML errors are shown with their line number.

The Element tab shows the last tapped element: type, ID, text, placeholder, label and app.

Data-driven values

Every time you type a value while recording, Understudy asks how to use it.

  • Use this exact text — written into the flow as is.
  • Read from test data — the flow gets ${output.Column} and the value goes into Excel as row 1.

Choosing the file and sheet

The first time, choose where data goes: an existing Excel file and sheet, an existing file with a new sheet, or a new file in TestData/. All data-driven values in one flow use one sheet; change it any time with Change under the steps.

Columns

The column name is suggested from the field (et_email → Email, “Enter your password” → Password), and the sheet's existing columns are offered. New columns are added at the end. A value already in row 1 is never overwritten. Reusing a column name reuses its value.

Click a value chip in the step list at any time to switch between exact text and test data.

Excel format

Plain .xlsx files in TestData/. Row 1 holds the column names; every other row is one test case.

EMAILPASSWORDEXPECTED
alice@example.comSecret1Home
bob@example.comSecret2Home

A flow loads one row with a runScript line, relative to the flow file:

  Flows/Login/login_valid.yaml
- runScript: "../../Scripts/LoginData/Valid.js"   # Scripts/<file>/<sheet>.js
- inputText: "${output.Email}"
  • Use letters, numbers, _ and - in file, sheet and column names. Column names are case-sensitive.
  • Empty cells become ""; blank rows and columns are ignored.
  • Cells are read as Excel shows them, so leading zeros and dates are kept.
  • Keep workbook names unique across TestData/ subfolders.
  • After editing Excel outside Understudy, press Prepare Data on the Run tab.

Excel editor

The Test data tab edits workbooks without leaving Understudy: edit cells, insert rows above/below and columns left/right, delete them, add sheets and create new files. A backup is written to ExcelBackups/ before every save. Formula and date cells are read-only, and the first 1,000 rows of a sheet are shown.

Running flows

  1. Prepare Data turns your Excel files into data scripts (it also runs automatically at start and after saving).
  2. Tick flows, click a tag, or load a saved suite. Flows run in the order you tick them; reorder them in the queue.
  3. Set Rows per flow, then Run Selected or Run All.

Options: Stop at any time, Stop the queue if a flow fails, and Rerun failed (exact flow and row). Save queue as suite keeps the order, rows and options under a name.

Each selected row is a separate test with its own report, shown as flow · row N. Selections are checked before the run starts. Sub-flows that load their own sheet always use row 1.

Results and reports

While a run is going, the Live run panel shows every Maestro step as it happens (running, passed, failed, time per step, sub-flows indented) next to the Excel row in use, with progress and elapsed time. Afterwards the first failure opens automatically, with its failure screenshot and the failing step highlighted. Each test writes one Maestro HTML report to Reports/, viewable inside Understudy.

Dashboard

Every run is saved to History/ (last 300 runs). The dashboard shows runs recorded, tests executed, pass rate and average run time; passed vs failed per run; the pass-rate trend; most failures; slowest tests; and flaky tests — tests that both passed and failed with the same data recently. Compare two runs lists what got fixed, what newly fails, what still fails, time changes, and the failed step.

Security and privacy

  • The server listens on 127.0.0.1 only. There is no telemetry and nothing is uploaded.
  • A new session token is created at every start. The app window receives it as an HttpOnly, SameSite=Strict cookie and sends it as a header on every change; requests with an unknown Host or Origin are refused. Other websites in your browser can't control Understudy.
  • adb and the emulator are started without a shell, and every argument sent to the device is quoted, so typed text can never become a command.
  • Flow, workbook, sheet, column, APK and device names are validated. Request bodies and uploads are size-limited; APKs are checked before they are stored.
  • Maestro's HTML reports are shown in a sandbox.

Limitations

  • Windows only for now; Android only (iOS simulators need macOS).
  • The device screen is frames, not video — about 5–10 per second on a virtual device.
  • Some apps refuse emulators (banking, root or emulator detection, Play Integrity). Use a real phone.
  • One device and one test at a time. Each data row starts Maestro again.
  • Close workbooks in Excel before saving them from Understudy.

FAQ

Do I need Maestro Studio or Android Studio?

No. You need the free Maestro CLI. Understudy records flows itself and can install the Android tools.

Is my APK uploaded?

No. It's copied into Apps/ on your PC and installed with adb.

Can I use flows I already have?

Yes. Put them in Flows/, or paste them into the recorder's Flow panel to edit them.
